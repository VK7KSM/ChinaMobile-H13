## 0. 路线决定（2026-09-18）

项目所有者在 2026-09-18 决定改变方法，理由和分析见当日对话结论：

1. 此前 v0.6 至 v0.80 的做法是从 Android 端用原始 HPI 重新实现模块的发射会话，而这条 External DMR 路径原厂应用从不使用，没有任何参考样本，只能猜；三次 setup0 加新鲜预检的流程把每个软件缺陷放大成一两个小时的真机仪式。
2. 新路线：**先在电脑上把 MCU 固件跑起来**（Cortex‑M0，完整 256 KiB Flash 和初始化 RAM 都已具备），让固件自己执行 `DMOPTT=1`，把它对 GPIO、HPI、时隙区和会话记录的每一次读写按序记录，得到原厂发射序列；**再用一次真机会话取原厂参考样本**（MCU 内被动记录钩子加 Android 端 `strace`）校正 SCT 黑箱应答；**最后让固件自己发射**，Android 只按 v0.79 已验证的节拍供 78 包软件 AMBE 数据，不再手写 RF 准备桩。
3. 流程改为：每个假设先在模拟器过，真机每个假设只做一次，重启作为标准复位；一次真机会话只回答一个“是或否”的问题。
4. 所有有价值的逆向资产整理后上传 GitHub `VK7KSM/ChinaMobile-H13`，之后每一步进展同步上传。

不变的约束：H13 只走 USB ADB、本机 5038 端口；内置硬件 PCM→AMBE 分支保持封存；任何可能发射的动作前停下取得当次许可；原始证据不覆盖。

## 2. 步骤一：MCU 固件模拟器（2026-09-18 开始）

### 2.1 已知输入

- 应用向量表位于 `0x08006000`：初始 SP `0x200056e8`，复位 `0x080060d1`，NMI `0x08012ce3`，HardFault `0x080129b1`，SVC `0x08021d27`，PendSV `0x08013387`，SysTick `0x08021ddd`；IRQ7（EXTI4_15）`0x08010ba9`，IRQ16（TIM3）`0x08021f79`，IRQ27（USART1）`0x0802251d`，其余 IRQ 指向默认处理 `0x080060e3`。这与 STM32F0 系列的中断编号表一致。
- 固件引用的外设块（对 Flash 做 32 位字扫描，只列与 STM32F0 外设图一致的高置信项）：RCC `0x40021000`（20 次）、USART1 `0x40013800`（6 次）、SPI1 `0x40013000`、USART2 `0x40004400`、USART3 `0x40004800`、EXTI `0x40010400`、SYSCFG `0x40010000`、FLASH `0x40022000`、TIM2/3/6 `0x40000000/0x40000400/0x40002000`、PWR `0x40007000`、GPIOB–GPIOF `0x48000400`–`0x48001400`、SCS `0xe000e000`。这确认了模拟器需要的内存映射：Flash `0x08000000` 256 KiB、SRAM `0x20000000`、外设 `0x40000000` 与 `0x48000000`、系统控制 `0xe000e000`。字扫描的其他命中多为指令位型，不作为外设证据。
- Cortex‑M0 没有 VTOR，固件把 48 字向量表复制到 SRAM `0x20000000` 并用 SYSCFG 重映射；模拟器的中断分派按 SRAM 向量表读取。
