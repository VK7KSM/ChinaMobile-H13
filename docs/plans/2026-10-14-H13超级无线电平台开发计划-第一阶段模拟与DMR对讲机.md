## 1. 愿景与范围

### 1.1 平台愿景（对接 §16 Radio OS）
把 H13 从一台固定功能的三合一对讲机，改造成一个以 SCT3258 射频模块为硬件底座、由我们自己的软件控制面驱动的**超级无线电平台**：本机 UHF 模拟 FM / DMR 收发 + 网络电台（BrandMeister / Zello / SIP）+ 窄带 SDR 辅助诊断 + 数据消息 + 与 24 小时基地服务器/远程电台/SDR 协同。H13 是随身控制终端，是整个分布式系统里**唯一的本机射频发射途径**（UHF 模拟/DMR）。

§16 已给出本机分层框架，本计划沿用：
```
H13 Radio OS（默认 Launcher，后续阶段）
  ├ Radio UI：频道 / TG / 频谱 / 地图 / 卫星 / 消息 / 设备状态
  ├ Key/PTT Router：大 PTT(F1/scan59)、小键一/二(m1/m2)，本地实时热路径
  ├ H13 Radio Service：SCT3258 UART + HPI，模拟 FM / DMR 收发 + DMR 数据消息   ← 本阶段核心
  ├ Network Radio：BrandMeister / Zello / SIP(liblinphone)                      ← 后续阶段
  ├ Audio/PTT Arbiter：一次只允许一个发射后端占麦克风+PTT（独占租约，异常/断链/超时自动松键）
  ├ Base Link：Wi-Fi/LAN 主，DMR 数据 + MeshCore 备
  └ Local Store：配置 / 离线任务 / 事件 / 待上传
```
铁律（§16）：PTT/松键/TOT/频率功率限制/音频占用**全走确定性代码**；AI/网络/界面绘制**不得进按键热路径**；AI 只产结构化计划，须过频段/模式/功率/TOT/权限校验，输出不得直接成 shell/串口字节/PTT。

### 1.2 第一阶段范围（本计划）
实现一台**完整的、我们自主控制的模拟 FM + DMR 数字对讲机**，即：
- 数字/模拟信道库管理（频率、功率、模式、色码/TG/时隙/加密、亚音 CTCSS/DCS、带宽、静噪、音量）。
- 模拟 FM 的接收（静噪/亚音）与发射（PTT 键控，本机原生调制）。
- DMR 的接收（硬件 AMBE 解码本机出声）与发射（本机原生编码上线）。
- PTT 热路径与频道切换、Audio/PTT 独占仲裁、设备恢复与安全关断。
- 为后续"超级平台"能力预留并打通关键深层接口：DMR 语音数据面（RX CHAN_D 导出解码、TX 中继注入）。

**不在第一阶段**：网络电台（BrandMeister/Zello/SIP）、完整 Radio UI/地图/卫星/频谱、宽带 SDR、任意波形。这些留后续阶段，且宽带 SDR / 任意波形已证硬件不可行（§1.4 边界）。

### 1.3 两层能力与总体策略（关键架构判断）
H13 对 SCT3258 有两层可用能力，本计划据此分层推进：

- **常规 AT 层**（`AT+DMO*` 文本协议，57600）：模块**原生**完成射频收发、编解码、PTT 键控。生产 `com.bozhou.interphone` 已证一套 APK + 当前固件 + 频道库**同时支持 DMR 与模拟 FM**，切信道即切数/模模式（`H13.md:2055-2066`）。这是**最快拿到"能用的对讲机"的路径，低风险、已被原厂实证**。我们的平台用同样的 AT 协议驱动模块即可获得完整本机收发。
- **深层 HPI 层**（raw UART-HPI 桥 / SRAM 一次性桩 / 语音数据面 / 中继回放 / 软件 AMBE）：绕过原厂 APK 直接操纵模块数据面，用于 DMR 语音**导出**（RX CHAN_D→PCM，录音/网络）与**注入**（PCM/AMBE→空口，网络桥/回放），以及模拟 PCM 注入。复杂、部分已闭环（本会话 v1.61）、部分未验收。这是"超级平台"的差异化能力。

**策略**：先用常规 AT 层把对讲机建成可用（阶段 1-3），再把深层能力逐层叠加（阶段 4-6），最后做网络与平台化（阶段 7+）。每层独立验收，互不阻塞。

## 2. 现状基线（已闭环成果，直接复用）

截至 2026-10-14，与本计划相关的已证成果：

### 2.1 DMR 语音发射（深层，中继路线，已空口达成）
- **已证**：从空口帧离线解出的**未编码 49 位 AMBE 参数**经 HPI 中继回放给模块、由模块自己做信道编码并发射，可被真·DMR 对讲机清晰接收。2026-09-20 TYT 听清 "one two three four five"（`new §2.8.83`）；2026-10-14 TYT 实听"与真·DMR 对讲机说话完全一样"（`new §2.9.82/§2.9.88`），本会话 v1.61 RF 收尾 fix B 真机一次通过、TYT 复听清晰。
- 发射质量两处修复：第三帧后移两单元补偿 **f3shift**（v1.57）+ 正文后尾部回送静音单元 **f3tail**（v1.58）。
- RF 收尾 **fix B**（v1.61）：RF 关断确认后跳过注定失败的全量文本面恢复，判 `result=PASS` + `reboot_required=true` + `rf_path_recovery_by_reboot=true`，走重启恢复；无重试风暴。宿主省电门②补丁已配套。
- 这条路线**不升速、不逆向内置编码器**，全程 57600，是本计划 DMR TX 的基线。

### 2.2 DMR 语音接收（深层，已实机跑通）
- **已证**：27 字节 CHAN_D（3×9 字节 AMBE，约 60ms）经 root APK + 原 UART + 只读 memread 从 MCU tape RAM 实时取出，离线 mbelib 标准 DMR 去交织 → AMBE+2 解码 → 8kHz/16bit/mono PCM（v0.16 21 单元 PASS，v0.17/18 跨 generation 603 帧 12.06s WAV）。接收链本身用模块**内置硬件 AMBE 解码器**（TG99 空口双向实测确认）。

### 2.3 控制面与安全机制（已证可复用）
- 57600↔230400↔57600 文本面往返可逆（v0.70，仅文本面）；自动退桥 SysTick one-shot（v0.31）；56 字节栈安全桩（v0.68+）；executeRfOff/attestRfOff 权威关断（ROF! marker）；5044/5条 SRAM 原像备份+逐字恢复；生产 Interphone 重新独占 `/dev/ttyHS0`、模块版本/GPIO/WiFi 核验框架。

### 2.4 内置硬件 PCM→AMBE 编码器逆向
- **已封存**（探针 v3.70，`AGENTS.md` 封存点）：步骤 6 状态"成果已封存、验收未完成"。本计划 DMR TX 不依赖它（走 2.1 中继路线）；未经项目所有者解封不得继续该分支。

## 3. 硬件与接口底座

### 3.1 射频链路（`H13.md:1690-1713`）
```
Android / MSM8909
  ├ /dev/ttyHS0 = 78b0000.uart（57600 8N1；DSP 升级 115200；libserial_port.so 另支持 230400/460800）
  └ /sys/boptt/* 板级 GPIO（电源/PTT/音频/PA）
      └ Cortex-M0 控制 MCU（STM32F0 兼容，USART1 base 0x40013800，PA9 TX/PA10 RX）
          ├ SCT3258  DMR/dPMR/模拟 基带 DSP（110.592MHz，8位并行 HPI 主机口，默认 AMBE+2）
          ├ SCT3811  直接变频 I/Q 接收前端（100-650MHz，经 HPI SPI_OPERATION(0x6D) 代管）
          ├ LMX2571  频率合成器（本振；§18 实机叙述另称 BK4819，以 §14 固件证据 SCT3811+LMX2571 为准）
          ├ TLV320AIC3204  外部双通道 codec（I2C 0x18，由 SCT3258 代管，24kHz/16bit/双时隙 TDM）
          └ PA + RF 滤波
```
模块版本 `AT+DMOGETSOFTVERSION → +DMOGETSOFTVERSION:0.3.66;V2.01.07I3`。Android 能"控制"模块 ≠ 能拿模块内部 ADC/DAC 原始 I/Q。

### 3.2 频段 / 带宽 / 功率（`H13.md:11344-11352` 等）
- **原厂天线工作频段 403-423 MHz**；433.550 MHz 用原厂天线实测 VSWR>4.0（易损 PA），须接 **50Ω 假负载**（VSWR=1.0）。AT 频率范围 100MHz-1GHz。
- 带宽：窄带 12.5kHz / 宽带 25kHz。
- 功率档位：power low/high → PowerLow/PowerHigh 8 点频率表 → 最近锚点 → runtime code+10 → MCU DAC1 ch1（12-bit，写 `0x20002DE6`）→ PA 偏置电压（慢速控制电压，不承载调制）。
- **实测功率码↔瓦数（433.550，假负载）**：出厂低功率码 **2030**（le16 `0x07EE`）→ 早期 ≈2.3W（CW）/ 本会话 ≈1.01W（DMR TDMA 突发，`new §2.9.79`）；码 1000 → <100mW。**功率码非线性未标定**，接任何功率值前必须瓦表 + 假负载/衰减实测，不可从码/credit 推瓦数。

### 3.3 关键接口语义
- **UART**：开口前 `ioctl(fd,0x5441,2)`=使能 UART 时钟（关=0x5442）；57600 8N1 阻塞读 ≥1 byte。隐藏控制台（memread/memwrite/print/sct3258*）与 Android 共用同一 USART1，**正常 AT 会话下 memread 无输出，须 `print 1` 打开**。生产 Interphone 独占串口，并行第二 fd 会使其 SerialPortReader 收 EOF。
- **HPI 包格式**：`84 A9 61 | LEN_hi LEN_lo（大端，不含前6字节）| TYPE | 字段...`，奇数长度补 1 个 `00`（不计 LEN）。packet type：0=控制/配置，3=主机送下一块数据，0x20=TX/近端队列，0x30=RX/远端队列。setter 正常响应 = 同 field + 状态 `00`（非回显参数），`17 06` 为拒绝。
- **音频通路（关键约束）**：codec 模拟链分工 = 左 ADC→麦克风、右 ADC→FM 解调输入、左 DAC→扬声器/VCO(TX)、右 DAC→VCTCXO（两点调制）；codec LOUT2/ROUT2→MOD_I/MOD_Q（`F3:106`）。**Android AUXPCM 未证接到模块**；RX 解调音频经独立模拟/PA 路径进扬声器，**不经公开 Qualcomm PCM capture 节点**；模块内 codec 24kS/s 不被公开 ALSA 端点接受。⇒ Android 侧拿不到连续原始 RF/I/Q，也拿不到解调后连续 PCM；语音数据面只能经 HPI 的 CHAN_D/SPEECH_SAMPLES 字段进出。
- **板级 GPIO `/sys/boptt/`（经 adb root 读写）**：`audio_switch`=GPIO23（SWITCH_MIC_PATH，TX 开始 200ms 后置 1）、`pa_enable`=GPIO69（RX 开始 200ms 后置 1；恒读 0 不反映发射状态）、`dmr_switch`=GPIO94+97（模块电源/复位）、`ptt_d`=GPIO112（模块↔AP 唤醒握手，非大 PTT）、`freq_section`；静默基线 `dmr_switch=1/audio_switch=0/pa_enable=0/ptt_d=in/freq_section=4`。大 PTT=GPIO36/KEY_F1。

### 3.4 SDR 能力边界（`H13.md:3585-3639`，供"超级平台"定位，勿越界承诺）
- **可做**：信道配置+模式切换、PTT、RSSI(`DMOGETRSSI`)、BER(`DMOTESTBERO153`)、芯片 ID/版本、DMR 数据帧收发、DMR 语音 CHAN_D 导出、窄带无线电终端功能、接收诊断/扫描。
- **不可做（仅软件，不拆机）**：连续原始 RF/I/Q、MHz 级宽带 SDR、任意采样率 ADC、任意波形 DAC、绕过模拟前端/PA 的任意调制。真宽带 I/Q 需拆机从 SCT3811 混频/滤波节点外接高速双 ADC。

## 4. 控制面技术要点汇编（数/模共用）

### 4.1 常规 AT 文本协议（57600，Android 直发）
查询/握手：
```
+DMOSTARTUP:0                                  模块启动上报
AT+DMOCONNECT        → +DMOCONNECT:0
AT+DMOGETSOFTVERSION → +DMOGETSOFTVERSION:0.3.66;V2.01.07I3
AT+DMOGETRSSI        → +DMOGETRSSI:<NB>,<WB>    两字节各减 0x89，例 -137,-75
AT+DMOGETDIGITALCH / AT+DMOGETANALOGCH / AT+DMOGETDIGITALRXINFO:0,0,0 / AT+DMOGETMESGINFO:0,0,0,0
```
信道设置（实机逐字）：
```
数字 DMR:
AT+DMOSETDIGITALCH=433550000,433550000,13,99,12345678,directmode,group,slot1,slot1,off,low,8,4,2,99 → +DMOSETDIGITALCH:0
  字段序:rxFreq,txFreq,colorCode,?,DMR-ID,mode,group,txSlot,rxSlot,privacy,power,colorCode?,volume,micGain,rxGroup
  （注意 AT 文本 slot1 实际被 TYT 识别为 TS2，字符串不可字面理解）
模拟 FM:
AT+DMOSETANALOGCH=418175000,418175000,wide,high,3,7,carry,0,carry,0 → +DMOSETANALOGCH:0
  字段:rxFreq,txFreq,带宽(narrow/wide),功率(low/high),静噪(0-9),音量(0-8),输入亚音类型,输入亚音码,输出亚音类型,输出亚音码
```
发射键控（实机 PASS）：
```
AT+DMOPTT=1 → +DMOPTT:0   且底层 +DMOSENDMOUDULESTA:TxStart   （合成器锁频 + 开 PA 偏置）
AT+DMOPTT=0 → +DMOPTT:0   且底层 +DMOSENDMOUDULESTA:TxEnd
```
其他：`AT+DMOSETMIC=0..2` 麦克风增益档；`AT+DMOSETPWRSAVELV=off`（进桥前须关，回读 `0x200017E1`）；`AT+DMOSETRECORDSW`/`AT+DMOSETPLAY`/`DMOAUTOUPDATARECORDINFO` 模块内录放（只给 voiceId/pack/block/page 索引，不给语音 payload）；`AT+DMOSENDMESG=<type>,<toId>,<length>,<hex>` 数据消息（type=group/IPconfirmation/IPnonconfirmation，接收上报 `DMOAUTOUPDATAMESGINFO`）。

### 4.2 信道数据结构（写频 / config，基址 0x200017B4）
- 228 字节总配置：`[0..43]运行头 + [44..203]数字信道 + [204..227]模拟信道`。`config[2]` 协议选择：0=DMR（实际接通）/1=dPMR（有代码未接入）。
- **数字信道**（`DMOSETDIGITALCH`→config+44 起，`H13.md:2594-2619`）：rxFreq+44 / txFreq+48 / DMR-ID+52（=CSBK fromId）/ groupId+56 / secretKey+60（8位hex，RC4 key=reverse(config[60..63])‖0x90）/ callType+64(ind/grp/all=0/1/2) / txSlot+65 / rxSlot+66 / channelMode+67(directmode/dcdmmode) / encryptOnOff+68 / power+69 / colorCode+70(0-15) / volume+71(0-8) / micGain+72(0-2) / receiveGroupCount+73 / privacy-init+74 / receiveGroups[32]+76。
- **模拟信道**（`DMOSETANALOGCH`→config+204 起 24 字节，`H13.md:2670-2690`）：rxFreq+0 / txFreq+4 / bandWidth+8(narrow=0/wide=1) / power+9(low=0/high=1) / squelch+10(0-9) / volume+11(0-8) / micGainPreset+12(0-2) / inputCtType+16(carry=0/ctcss=1/ndcs|idcs=2) / inputCTCSS+17(0-50) / inputDCS+18(0-82) / inputDCSpol+19 / output 同上 +20..+23。
- **写频工具**：泉盛 `DMRConfigTool_V2.1.0.6`，无私有 USB 协议，用 adb push/pull/shell + 广播 `android.intent.action.INI_READ`（触发 `sys.dmr.file`，生成 `/sdcard/configuration.txt`）。信道行 `type=0` DMR / `type=1` 模拟。

### 4.3 MCU 内建 HPI 收发函数（固件，深层直控时首选复用，勿自写驱动）
| 地址 | 功能 |
|---|---|
| 0x08010290 | SCT3258 硬复位（GPIOA pin11 高1ms→低500ms→高100ms） |
| 0x0800FDB0(mode)/0x0800FFB4(mode) | 复位后下载 2048-byte loader（mode 0 基础/1 基础+HPI维护/2 DMR system-Flash），完成写 0x200000E5 |
| 0x08010560(buf,len) | HPI 原始字节写（逐字节 PD0..7，GPIOF pin6 选通） |
| 0x0800FFC8() | HPI 原始单字节读 |
| 0x080102D0 / 0x080103EC | 单段/双段 Packet Interface 发送（0x20000DE2 构造 84 A9 61 帧，奇数补 00，body+6≤256） |
| 0x080105C8(out_len,out_status,out_payload,timeout) / 0x0800FFF8(~300ms) | 同步接收（滑动同步 84 A9 61，读大端长度，byte5=状态/类型，byte6+=payload） |

### 4.4 SCT3258 HPI 字段命令集（经 raw bridge 或 Packet Interface）
```
0x10 VOCODER_SEL      4=AMBE+2（数字）/ 16=Analog（模拟）
0x18 WORK_MODE        正文 18|workmode|(modemloop<<4)|audioloop|debug；workmode 0=Idle/1=RX/2=TX/3=FullDuplex
0x1A PROCESS_MODE
0x26 ANALOG_SUBAUDIO  CTCSS/DCS 位编码（carry/ctcss/ndcs/idcs）
0x2D CODEC_SELECT     1=TLV320AIC3204 / 2=WM8758B / 3=ES8338
0x3C ANALOG_CONFIG    bandWidth narrow→00b / wide→11b（IF/BB_CH_SEL）
0x3D CTC_PARAM        CTCSS 检测参数
0x3E VOCODER_IO_SET   语音路由位图（见下），成功回 3E 00
0x40 (codec 寄存器转发) 00 PAGE REG VALUE 00 00，等 ACK 17 00
0x6C SQ_LEVEL         静噪阈值（两张 10 项表 0x20002ccc/0x20002ce0）
0x6D SPI_OPERATION    转发 SCT3811 寄存器（6D REG VAL / 6D REG VAL_MSB VAL_LSB）
0x68 DIGI_MIC_GAIN / 0x69 DIGI_SPEAKER_GAIN
0x00 SPEECH_SAMPLES（PCM块）/ 0x01 CHAN_D（编码语音）/ 0x7F DMR_SLOT_FOUND（RX 同步事件，值0=MS sync未报）
```
**VOCODER_IO_SET(0x3E) 位图**：bit7 Voice In(0=Codec/1=File-HPI)、bit6 Modem In、bit5:4 Vocoder Out、bit3 Decoder In、bit2 Modem Out、bit1:0 Voice Out。已知组合：0x04 远端 modem 输出文件 / 0x09 本地解码路由(Decoder IN=file 0x08 | Voice OUT=file 0x01) / 0x20 近端 vocoder 输出文件 / 0x40 外部 modem 输入 / 0x60 EXT_ENC_TX / 0x0C EXT_ENC_RX / 0x80 Voice In=HPI / 0x90（实机被 mode0 接受）。

### 4.5 波特率 / bridge flag（深层）
- `0x08010A00(r0=baud)`：仅当 bridge flag `0x2000015C==0` 时接受调用方 baud，非零强制 115200 ⇒ 230400 切速必须在置桥**前**完成。
- bridge flag `0x2000015C`：USART1 RX IRQ `0x0802251C` 每字节先读：=0 写 ASCII 命令 ring；≠0 逐字节直写 SCT HPI（Android↔SCT 透明转发）。上电 0；`sct3258reset` 不改；正常置 1 仅 `sct3258dspupdate`。
- **本阶段 DMR TX 中继路线不升速**，全程 57600（见 §6.2）。

## 5. 模拟 FM 收发实现要点

### 5.1 接收（本机原生，低风险）
- 进模拟 RX：`AT+DMOSETANALOGCH=<rx>,<tx>,<带宽>,<功率>,<静噪>,<音量>,<输入亚音类型>,<输入亚音码>,<输出亚音类型>,<输出亚音码>`（或写 configuration.txt `type=1` 行），模块自动进模拟接收、静噪/亚音由 DSP（`SQ_LEVEL 0x6c` / `ANALOG_SUBAUDIO 0x26`）完成，解调音频经模块模拟/PA 路径出扬声器。
- 亚音码表（本机固件权威）：CTCSS 51 项（第 1 项 62.5，…，254.1）；DCS 83 项（023…754），ndcs/idcs 同码表正/反极性；carry=载波静噪无亚音。
- 诊断：`AT+DMOGETRSSI`（窄/宽带 RSSI）。
- 【已证】原厂同一 APK + 频道库切模拟信道即模拟接收可用（`H13.md:2059-2066`）。我们的平台只需复刻该 AT 流程。

### 5.2 发射（本机原生键控，物理载波已证；音频调制通路是最大缺口）
- 物理发射序列**100% 可重复**（`H13.md:11298-11316`）：`AT+DMOSETANALOGCH(…)` → 写低功率码 2030 → `AT+DMOPTT=1`（等 TxStart，合成器锁频 + PA 偏置）→ 发射 → `AT+DMOPTT=0`（TxEnd）。
- ★**最大未解缺口（模拟 FM TX 出音）**：仅经 HPI 注入 PCM 并拿 credit **不会**自动产生物理载波，且即便 `AT+DMOPTT=1` 开了载波，注入 PCM 后接收机也只收到**纯净 CW 载波、听不到音**（`H13.md:11337-11363`）。因为麦克风模拟音频→模块的 FM 调制输入通路未打通。硬件级证据指向：codec 左 DAC→VCO 调制（WORK_MODE_TX 文档化状态）+ VCO/VCTCXO 线输出增益（P1_R18/R19，在 `DMOSETANALOGCH` 期由 `0x0800FA6C` 已应用）+ `/sys/boptt/audio_switch=1` 切麦克风通路。但"注入 PCM 出音"在 H13 上**未证**。
- **重要澄清**（`F2:150-191`）：原厂 TX 进入前的 codec 五写（P1_R16/R59、P0_R86/R87/R88）是**输入 AGC/扬声器静音**，不是 DAC→VCO 调制路由，不能当作缺失的调制桥。
- 结论：模拟 FM 发射分两种可达程度——
  1. **用麦克风直接发（最可能可达）**：复刻原厂"切模拟信道 + DMOPTT 键控 + audio_switch=1 走麦克风模拟通路"，让模块像原厂一样从麦克风采模拟音调制发射。这是原厂实际工作方式，应优先验证；若成立，模拟 FM TX 本阶段即可用。
  2. **注入任意 PCM 发（深层，未证）**：把任意音频经 HPI 注入作为 FM 调制源，用于网络中继/回放。未打通，列为深层缺口（阶段 6）。

### 5.3 收尾（stock 多拥有者，勿臆造）
- `AT+DMOPTT=0` stock 收尾：整体关断 `0x0801FF34`（DAC1=0→PF3 high→PC13 low→PE6 high）+ 恢复 `CARRIER_READY [19,1/2]`。三种 vendor teardown 不可互换；STOP_CALL=包类型 0 body `[0x21]`（≠ DMR_EndCommand 的 type3）。有效 codec 恢复 = stock 信道重应用（`DMOSETDIGITALCH→…→0x0800FA6C` + `0x0800FB62` 关 TX 时左 AGC）。

## 6. DMR 数字收发实现要点

### 6.1 接收（硬件 AMBE 解码，本机出声 + 可导出 PCM）
- **本机出声（低风险）**：`AT+DMOSETDIGITALCH(…)` 设色码/TG/时隙/加密/功率，切 DMR 信道，模块内置硬件 AMBE 解码器（UHF RX→SCT3811→SCT3258 DMR 解调/AMBE 解码）直接本机播放（TG99 空口双向实测确认）。接收组、RSSI、`AT+DMOGETDIGITALRXINFO` 轮询。
- **语音数据面导出（深层，已实机）**：一个 27 字节 CHAN_D = 3×9 字节 AMBE（≈60ms，含 49 位声码器参数 + Golay/Hamming FEC，不含同步字/CACH/slot type）。解码 8kHz/16bit PCM、每 20ms 160 采样，3 PCM 帧 ↔ 一个 27 字节单元。导出靠 root + 只读 memread 读 MCU tape RAM（44 字节管理头 `0x20001C00`、4 字节块标记 `0x20001C2C`=小端 0xa1b2c3d4、数据区 `0x20001C30` 起），或 raw HPI 读 SRAM 环形队列（`0x200042fe`，4 项×28 字节）。离线 mbelib：标准 DMR air interleave、字节正序、MSB-first、dibit 高位在前。隐私=标准 RC4（9 字节 KSA 输入，丢弃前 256 字节，每 9 字节帧只异或前 49 位）。
- **限制**：原厂 AT 接口不返回 CHAN_D 载荷（只给录放索引）；模块通话结束不留稳定非零 count（换块归零），须活动中采集；57600 连续 PCM 吞吐不足（需 ~16KB/s，57600 上限 ~5760B/s）。

### 6.2 发射（本机原生键控 + 深层中继注入）
- **本机原生发（低风险）**：`AT+DMOSETDIGITALCH(…)` + `AT+DMOPTT=1/0`，模块从麦克风采音、自编 AMBE、按设定色码/TG/时隙/加密发射。这是原厂 DMR 发话方式，应优先复刻，本阶段即可得可用 DMR 对讲机发射。
- **深层语音注入（已空口达成，中继路线）**：把**未编码 49 位 AMBE 参数**经 HPI 中继回放给模块、模块自做信道编码发射（用于网络桥/BrandMeister/录音回放）。关键要点（`new §2.x`，本会话 v1.61）：
  - 线上单元（包类型 3）：`84 a9 61 00 1d 03 01 1b <27字节> 00`。
  - 帧内 = 未编码 49 位参数，**高位在前、左对齐打包进 9 字节、余 23 位置零**；静音帧 b0=124（如 `f85399488c7c800000`）。离线判据：正确素材 c0_errors=0，模块经 HPI 交出的帧 c0_errors≈1.49（证明不含信道编码）。
  - 控制链：setup0 `84 a9 61 00 02 00 19 00`（严格 8 字节确认）→ setup1 `02 18`/setup2 `3e 60`/setup3(type5) `6f 8x`/setup4 `18 02 00 00`(WORK_MODE=TX) → codec 五写（增益取 `0x20002e25`）→ 两条 VLC 头(首字节 0x01/0x11，样本 `43 01 09 00 00 40 00 00 63 00 00 0d`)。
  - 供数：60ms 节拍一对一回送 27 字节单元，每单元等模块 `17 0a`（约 400ms）；正文后 500ms 尾窗回送静音单元（f3tail）；第三帧列整体后移两单元（f3shift）。
  - 两桥模型（**不升速，全程 57600**）：第一桥（无射频接口桥，SysTick 递减绝对退出计数自动退桥，`FIRST_BRIDGE_EXIT_MS`≥44580ms for 28.8s）；第二桥（射频，`SECOND_BRIDGE_EXIT_MS=3000`，`RF_HOLD_MS≈16s`，单次射频≤30s 发热限）。bridge flag `0x2000015C`。
  - 桩：生产桩 `h13_mcu_combined_multitick_runtime_mirror_v005.bin` 载 SRAM `0x20002f00`，元数据 `0x20003050`，退出计数 `0x20003058`，SysTick 向量槽 `0x2000003c`→原厂 `0x08021ddd`。仅用 56 字节栈安全桩（EXC_RETURN 规则见 §8.4）。
  - RF：信道 433.550/色码 8/时隙一/TG99/privacy-off，功率码 2030（≈1.01W），假负载。权威关断 executeRfOff（写 `VECTOR=RF_OFF_ENTRY`，核 ROF! `0x21464f52`@`0x200031c0` + gate0）。
  - fix B：RF 后文本面约 10.7s 死（时间触发事件，疑省电旗标 `0x200017e1`），RF 路径跳过全量文本面恢复、判 PASS+reboot_required，收尾 `pm enable --user 0 net.elfradio.h13interphone`→`adb reboot`→`am start`。

### 6.3 软件 AMBE 声码器（已就绪，PCM↔AMBE 互转）
- 探针内置 `libh13_ambe.so`（armeabi-v7a，imbe_vocoder + mbelib + MBEEncoder），线程安全 JNI。核心 C API：
  - `ambe_encode_dmr(enc,int16_t* samples,uint8_t* out)`：160 PCM(20ms/8kHz)→9 字节 72-bit 空口码字（含 FEC/交织）。
  - `ambe_encode_49bit_packed9(...)`：160 PCM→9 字节 **packed-49bit** 参数（MSB-first，供中继注入直接用）。
  - `ambe_channel_encode_49bit_packed9(packed49,out)`：packed49 + DMR FEC/白化/交织→9 字节空口。
  - 解码对称：`ambe_decode_dmr` / `ambe_decode_49bit_packed9` / `ambe_channel_decode_to_49bit_packed9` / `ambe_decode_dmr_reference`（离线参照）。增益编码 2.5/解码 3.5。
  - 位序常量 `vendor/ambe/vocoder_tables.h`（BIT_MASK MSB-first、DMR_A/B/C_TABLE、PRNG）；去交织表 `ambe_wrapper.cpp`。
- JNI：`SoftwareAmbeEncoder.nativeEncode49BitPacked9Batch(short[])` / `nativeEncodeBatch(long,short[])`，`SoftwareAmbeDecoder.*`；PCM 须 160 整数倍。
- 用于：RX CHAN_D→PCM（解码本地化/录音/网络上行）、网络下行 PCM→packed49→中继注入发射。
- 【未证】实时 PCM→AMBE 的 H13 性能（每 20ms 一帧耗时/丢帧/CPU）与完整组帧合同（第 4 帧与 36 字节关系、privacy 位置）仍待验收（AGENTS 步骤 7）。

### 阶段 3 — DMR 数字对讲机（本机原生收发）
- 目标：DMR 的接收（硬件 AMBE 出声）+ 发射（麦克风直发）可用。

### 阶段 4 — DMR 语音数据面导出（深层）
- 目标：RX CHAN_D→AMBE 解码→PCM，本地录音/解码（网络化基础）。

- 验收：回放一段素材，TYT 实听清晰（已达成基线）；推进到"网络下行 PCM→packed49 实时注入"需先过阶段 6a 性能门。
- 遗留边界：**第二轮语音信用不重启**（热点连续多呼需另解）；**RF 后文本面必死需重启**（生产化缺陷，须固件侧定位省电旗标 `0x200017e1`）。

### 阶段 6 — 深层缺口攻关（并行/按需）
- 6a 软件实时 PCM→AMBE 性能与组帧合同验收（AGENTS 步骤 7 门：无射频每 20ms 一帧耗时/丢帧/CPU、组帧位序、内容因果对照、连续三次稳定）。

### 阶段 7+ — 超级平台能力（后续计划，不在本阶段实现）

- 武装前读验 bridge flag/原向量/临时窗/将替换字节，按字上传整段回读核对精确哈希；改现场动作先把将改地址范围完整原始字节落盘（SRAM 不得只存哈希），写后/恢复后各再完整回读落盘。
- 只恢复自己改过的区域（new v1.60 原则，不含 session_queues）。

## 9. 风险、安全与发射纪律

### 9.1 已知技术缺口/边界（产品化前必须正视）
1. **模拟 FM 任意 PCM 注入出音未打通**——注入 PCM 只得纯 CW 载波（§5.2）。模拟 FM 麦克风直发可能可达（原厂方式），任意 PCM 注入属深层未证（阶段 6b）。
2. **DMR TX 第二轮语音信用不重启**——热点连续多呼未解（阶段 6c）。
3. **RF 后文本面必死（~10.7s）**——目前只能重启恢复（fix B）；生产化需固件侧定位省电旗标 `0x200017e1`（阶段 6c）。
4. **软件实时 PCM→AMBE 性能/组帧合同未验收**（阶段 6a）。
5. **V2.01.07I3 精确固件镜像不可得**——0x3E bit7 选择器与 1283 字节 type-3 消费者无法从公共应用反汇编，是首要兼容性缺口。
6. **宽带 SDR / 任意波形硬件不可行**（§3.4），超级平台定位不得越界承诺。

### 9.2 安全与发射纪律（不可削弱）
- **每次真机发射前，必须取得项目所有者当次明确"可以发射"**；过去许可一次一用、不顺延。假负载 + 低功率码 2030；单次射频 ≤30s（发热）；原厂天线仅 403-423MHz，433.550 须假负载。
- 真机实验遵守工作区历史证据去重门、预登记门、原始数据强制归档门；内置 AMBE 编码器逆向封存不得擅自解封。
- 发射质量判据以真·DMR 对讲机（TYT）实听/录音为权威；SDR 仅留档，解不出不影响结论；RX888 借用须经 flight 协调、用毕 `fx3_tool reset` 归还。
- 不改既有对讲/电话/独立守护；不影响生产 Interphone 的默认独占与基线恢复。

### 9.3 资源与额度
- 本阶段为本机射频 + 本地软件，不涉 Cloudflare 额度；进入阶段 7 网络电台时，BrandMeister 走 H13 Wi-Fi 直连 BM Master（不经本地热点/射频绕行），另计。
