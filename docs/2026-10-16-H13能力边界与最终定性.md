# H13 能力边界与最终定性（先读）

- 日期：2026-10-16（悉尼）
- 性质：基于约两个月的 H13 逆向（DMR 发射闭环、接收数据面、模拟/射频硬件、SCT3258 固件/厂商工具）与本轮对"模拟音频能否取出"的五角度封闭测试，得出的**务实定性**。供所有会话在对 H13 做任何规划前先读，避免重复已被钉死的弯路。
- 配套证据文档：`H13_new.md §2.x`（DMR 发射中继路线）、`2026-10-15-模拟FM音频无法经HPI进出-离线三层判定.md`（模拟音频五角度封闭）、`H13.md §14/§16/§17`（硬件/Radio OS/固件）、`docs/plans/2026-10-14-H13超级无线电平台开发计划-第一阶段模拟与DMR对讲机.md`（第一阶段计划）。

---

## 一句话定性

**H13 不是"超级无线电平台"的核心，它是平台里一个便携的 UHF DMR/FM 语音终端 + 经 Wi-Fi 的网络 DMR（BrandMeister）口。** 宽带 / 全模式 / SDR / HF / VHF / 模拟信号解码类玩法归**基地 SDR**（见 `H13.md §16` Radio OS 分布式架构），H13 当控制与本机语音终端，别指望它一机通吃。

## H13 已证能做

- UHF 本机**模拟 FM 语音对讲**（自收发、本机出声，麦克风直发）。
- **DMR 本机语音对讲**：硬件 AMBE 解码本机出声；**软件把 DMR 语音注入空口已达成**，对端 TYT 实听"与真·DMR 对讲机完全一样"（v1.61，RF 收尾 fix B 真机通过，见 `H13_new.md §2.9.77–2.9.88`）。
- **DMR 数字语音数据面**：RX 的 27 字节 CHAN_D / 160 样本 PCM 经 HPI 导出 + 软件 AMBE 解码成 WAV（录音、BrandMeister 网络化的基础，已实机）。
- **控制面 AT 协议**（信道 / 频率 / 功率 / 数模模式 / 亚音 CTCSS·DCS / 静噪 / 音量 / PTT）+ RSSI / BER 诊断。
- **DMR 数据消息**（`AT+DMOSENDMESG`）。

## H13 已证做不到（硬件/架构天花板，软件翻不过去）

- **模拟音频导出/注入：五角度全封。** HPI 导出、NAND 录音机、Android ALSA 采集、AUXPCM 路由（真机实测连打开都打不开）、模拟 line-in 全部关闭；模拟 FM 音频焊死在模块 codec→扬声器，Android 侧没有任何采集口能听到它。→ **APRS / SSTV / 录模拟信号 在 H13 本机不可行。** 详见 `2026-10-15-模拟FM音频无法经HPI进出-离线三层判定.md`。
  - 根因：H13 是两套物理隔离的音频硬件——Android(MSM8909+WCD codec) 与 射频模块(SCT3258+TLV320AIC3204)；Android 能遥控模块，但模块音频只在模块自己的 codec→扬声器，没有电气通路引进 Android 音频输入。TX 注入（模拟）与 RX 导出（模拟）同根，两头都不通。数字 DMR 例外，因为语音编码成 AMBE 数字帧（CHAN_D）可沿 HPI 数字链进出。
- **频段只 UHF ≈400–430 MHz**（原厂天线 403–423，433.55 须假负载）；无 VHF/144/HF，SCT3811 虽可调谐但 PA/滤波/天线是 UHF。
- **模式只 模拟FM / DMR / dPMR**；无 SSB / AM / C4FM / P25 / NXDN / 宽带 SDR / 任意波形。
- **不拆机拿不到连续原始 RF/I·Q，也拿不到解调后连续 PCM**；非宽带 SDR。
- **MCU 固件重刷未建立且高风险**（逆向刻意用 SRAM 一次性桩避免永久改固件；Flash 整片读回从未成功、写/擦/program 命令禁用）。
- **生产化缺陷**：DMR 第二轮语音信用不重启（热点连续多呼未解）；RF 发射后文本面约 10.7s 必死、须重启 MCU 恢复（fix B）。
- **硬件本体**：MSM8909 低端 SoC、Android 8.1（旧）、扬声器音质一般。
- 精确固件镜像 `V2.01.07I3` 不可得（首要兼容性缺口）。

## 定位与分工（Radio OS §16）

- **平台的"大脑"在基地**：24 小时服务器 + 真 SDR（RX888 / RSP1）+ IC-735 / TH-9800 + 天线阵。宽带接收、全模式、HF/VHF、SDR/APRS/SSTV/频谱等重活都在基地做。
- **H13 是平台的"随身嘴+手"**：UHF 本机 DMR/FM 语音对讲、本机 PTT/频道、经 Wi-Fi 上 BrandMeister 的网络 DMR、DMR 数据消息、设备状态/诊断。它残，只说明它当不了大脑，不等于平台不成立。

## 对开发计划的含义

- 第一阶段 H13 侧目标收敛为：**可用的 UHF 模拟 FM + DMR 语音对讲机** + **DMR 数字数据/录音/BrandMeister 网络**；按第一阶段计划阶段 0–5 推进。
- **阶段 6b（模拟 FM 任意音频注入/导出）判死**，从计划划掉或标"硬件不可行"。
- **不把 APRS / SSTV / SDR / 全模式 / VHF / HF 排进 H13 本机**——这些放基地 SDR，或属"换更强硬件"的决策，不是再写代码能救的。
- 若目标是真·手持 SDR/全模式机：H13 不是这块料，是换硬件的事。

## 价值留存

这几个月不是白搞：**DMR 收发数据面（空口帧结构、49 位 AMBE 参数回放、组帧/privacy/VLC/信用、RF 键控与收尾）被整条啃下来**，这份能力与 IP 跟 H13 本身强弱无关，换到别的 SCT3258/DMR 平台一样通用。已钉死的"做不到"也是结果——是实测的"不可能"，省掉以后往死胡同再砸时间。
